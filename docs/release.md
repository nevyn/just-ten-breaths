# Releasing

Automated via `.github/workflows/release.yml`, triggered by publishing a GitHub Release.
Runner: `macos-26`. CI builds, signs (Developer ID), notarizes, and attaches the zip.

## Cutting a release

```bash
./release.sh minor   # 2.1 → 2.2
./release.sh major   # 2.1 → 3.0
./release.sh redo    # re-release current version (bumps build, deletes old release+tag)
```

Pass `--dry-run` to preview. The script bumps the pbxproj version, commits, pushes, and
creates the GitHub release; release notes are generated by `claude -p` from the tag-to-tag
commit log and Swift diff (falls back to `--generate-notes` when the CLI is unavailable —
e.g. it can't authenticate from an agent's shell).

## Signing

- Bundle ID `dev.nevyn.just-ten-breaths`, team `M4Q2TE45WT` (personal, never FR24).
- Release config: Manual signing, `Developer ID Application` identity. The provisioning
  profile name is passed via the `JTB_APP_PROVISIONING_PROFILE` build setting (applies only
  to the app target). Debug: Automatic.
- A provisioning profile is required even for Developer ID, because of HealthKit.

## Required repository secrets

| Secret | Value |
|--------|-------|
| `DEVELOPER_ID_P12` | Base64-encoded Developer ID Application cert + key |
| `DEVELOPER_ID_P12_PASSWORD` | P12 export password |
| `PROVISIONING_PROFILE` | Base64-encoded Developer ID provisioning profile |
| `APPLE_ID` | Apple ID email |
| `APPLE_ID_PASSWORD` | App-specific password for notarization |

## Verifying an artifact

```bash
spctl -a -vv "just ten breaths.app"   # expect: accepted, source=Notarized Developer ID
```
